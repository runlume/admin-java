# Java Javadoc 规范

## 1. 目标

Javadoc 记录类型系统和名称无法完整表达的契约：职责边界、资源隔离、前置条件、失败、幂等、事务、并发和资源上限。注释不能成为逐行复述代码的模板税。

采用项目必须在开发 Profile 中声明文档语言、传统 `/** */` 或 `///` 风格、类级 `@author`/`@since` 格式、必写可见性以及自动检查入口。同一源码文件不混用两种文档注释风格。

## 2. 必须文档化的对象

通用最低要求：

| 对象 | 要求 |
|---|---|
| 对外或跨模块公开类型/方法 | 说明职责、边界、参数、返回和失败语义 |
| API/SDK 类型 | 说明版本、幂等、鉴权、兼容和敏感数据规则 |
| Web 映射方法 | 说明用途，并按需说明可信身份、资源归属、幂等、事务和失败边界 |
| Aggregate、Policy、状态机 | 说明不变量、合法转换、并发和所有权 |
| 公开 record 组件 | 使用 `@param` 说明非显然约束 |
| 业务枚举值 | 状态、权限、外部编码或安全含义非显然时逐项说明 |
| 公共常量/配置 | 说明单位、范围、默认值、上限和变更影响 |
| 复杂私有算法或安全步骤 | 说明为什么存在、关键不变量和失败关闭行为 |

是否要求所有生产顶层类型、非公开成员或所有 Web 映射方法文档化，由项目 Profile 明确。简单 getter/setter、显然私有委托、测试夹具和纯字段 Mapper 不添加模板注释，除非项目门禁另有要求。

Controller 的完整分工见[OpenAPI 与 Controller 开发规范](openapi-and-controller-guidelines.md)。类级说明不能替代映射方法自己的 Javadoc。

## 3. 基本格式

首句使用项目统一语言写简短完整摘要并以句号结束。正文解释“为什么、边界和失败”，不描述每行实现。Javadoc 位于声明的所有注解之前。

```java
/**
 * 为已验证的服务主体签发短期访问令牌。
 *
 * <p>主体身份和资源归属来自可信认证上下文，调用方不能通过请求体覆盖。</p>
 *
 * @param command 目标资源和申请权限；不可为 {@code null}
 * @return 最终获批权限的短期令牌；不会返回 {@code null}
 * @throws ResourceNotFoundException 当资源不属于当前主体时抛出
 * @throws PermissionDeniedException 当申请包含未获授权权限时抛出
 */
AccessTokenResult issue(ServiceTokenCommand command);
```

自然语言与英文、数字、`{@code}` 之间使用一致空格。多段正文使用 `<p>`；列表使用 `<ul>/<ol>`。代码、值和字段名使用 `{@code}`，类型/方法关联使用 `{@link}`，多行示例优先 `{@snippet}`。

## 4. 标签顺序与元数据

块级标签顺序：

1. `@param`（含泛型和 record 组件）；
2. `@return`；
3. `@throws`；
4. `@author`；
5. `@since`；
6. `@deprecated`；
7. `@see`。

作者和值版本不能在通用规范写死，项目 Profile 应提供唯一模板，例如：

```java
 * @author Example Team
 * @since 1.0
```

- 类级元数据表示该类型首次加入代码库时的事实；后续修改、移动或重构不随意刷新。
- 方法、构造器、字段和枚举值默认不添加 `@author`；是否添加 `@since` 由公开兼容策略决定。
- 自动检查验证项目 Profile 指定的作者、版本/时间格式和必写范围。

## 5. 类型文档

公开类型按适用项说明：

- 负责什么、不负责什么；
- 属于哪个模块、用例或边界；
- 拥有的事实与允许依赖；
- 非显然的并发/线程安全语义；
- 生命周期、兼容和失败关闭规则。

```java
/**
 * 管理资源的生命周期状态转换。
 *
 * <p>本服务拥有本地状态，不负责远程系统内部数据。远程调用在本地事务提交后执行。</p>
 *
 * @author Example Team
 * @since 1.0
 */
public interface ResourceLifecycle {
    // ...
}
```

实现类覆写已有完整接口契约时不复制 Javadoc，也不添加只有 `{@inheritDoc}` 的空注释。实现引入锁、缓存、降级或不同事务语义时，只记录实现增量。

## 6. 参数、返回与异常

- `@param` 说明空值、空白、长度、单位、来源可信度及跨字段关系，不写“ID 参数”。
- `@return` 说明空集合、缺失、拒绝、部分成功和顺序语义；默认不返回 `null`。
- `@throws` 只记录调用者可理解且应处理的异常，说明触发条件，不罗列基础设施细节。
- 幂等方法说明重复 key 的返回和同 key 不同载荷行为。
- 事务方法说明原子事实和外部副作用何时发生，不能承诺实现不了的 Exactly Once。
- 安全入口说明身份来源、Audience/Scope/Permission 和资源归属，禁止只写“校验权限”。
- 映射方法的 Java 参数按项目规则提供 `@param`；服务端内部参数不能因此进入外部 API 契约。

## 7. Record 与枚举

```java
/**
 * 资源预占键。
 *
 * @param tenantId 资源所属租户；不可为 {@code null}
 * @param consumerId 消费主体；必须属于 {@code tenantId}
 * @param resourceKey 资源标识；不可为空白
 * @author Example Team
 * @since 1.0
 */
public record ReservationKey(
    UUID tenantId,
    UUID consumerId,
    String resourceKey
) {}
```

业务枚举值说明能否进入、能否写入、是否终态或外部映射。机械翻译常量名没有价值。纯内部且语义显然的技术枚举不要求逐项模板注释。

## 8. 禁止内容

- `@param name 名称`、`@return 返回值` 等复述；
- 与代码、OpenAPI、Schema 或设计文档冲突的过期规则；
- 未经确认的性能、安全、事务或可用性承诺；
- Token、Secret、真实账号、生产 URL 和业务数据示例；
- 用 Javadoc 隐藏应由类型、数据库约束或测试表达的不变量；
- 为满足覆盖率批量生成无信息注释。

弃用 API 同时使用 `@Deprecated` 和 `@deprecated`，说明原因、替代 API 与迁移条件；没有替代方案时明确说明。

TODO 必须关联工作项并说明移除条件；不能把未完成安全校验写成普通 TODO。

## 9. 自动检查

采用项目的统一构建检查至少应阻断：

- 无效标签、坏链接和非法 HTML；
- `@param` 与实际参数/record 组件不一致；
- Java 解析或 Javadoc 任务失败；
- 项目 Profile 规定的类型/成员缺少 Javadoc；
- Web 映射方法缺少 Javadoc 或参数标签不一致；
- 类级作者、版本或时间不符合项目模板。

源码门禁只扫描生产源码，并包含故意违规夹具或非空断言，避免路径错误时空绿灯。自动化只能检查结构和格式，职责边界、失败语义和内容质量仍由评审阻断。

## 10. 评审清单

- [ ] 项目 Profile 已声明文档语言、风格、元数据模板、必写范围和检查入口。
- [ ] 公开契约说明职责、隔离、失败、幂等和事务语义。
- [ ] Web 映射方法有自己的 Javadoc，Java 参数标签与代码一致。
- [ ] 首句完整，注释没有复述名称或复制完整 Wire Contract。
- [ ] 参数、返回、异常和 record 组件与代码一致。
- [ ] 身份、权限和资源归属等信任边界描述明确。
- [ ] 覆写方法没有复制接口文档。
- [ ] 示例不含 Secret、生产数据或不可执行承诺。
- [ ] Javadoc/源码门禁实际执行且扫描目标非空。
