# 数据库版本与 Migration 开发规范

## 1. 适用范围

本文约束关系型数据库的 Schema 版本、Migration、数据回填、权限、代码生成输入和发布恢复。它不固定数据库产品、版本、迁移工具、目录、数据访问框架或具体业务维度；采用项目必须在自己的开发 Profile 中声明这些值。

开始变更前必须阅读本规范、采用项目的 Profile、目标模块数据所有权和当前交付计划。

## 2. 项目 Profile 必填项

每个项目至少声明：

- 数据库产品、受支持版本和生产补丁策略；
- Schema 唯一真源及 Migration 工具；
- 每个数据库/Schema 的拥有应用、迁移目录和版本命名；
- 业务数据访问方式及直接 SQL/JDBC 例外流程；
- Codegen 来源、输出目录、生成物提交策略；
- 租户/资源隔离维度、数据库角色和 RLS 策略；
- 空库、升级、权限、备份恢复和生产发布验证命令。

应用只能迁移自己拥有的数据库或 Schema。不同交付物即使共用数据库进程，也必须明确逻辑所有权、账号、History 和跨边界访问规则。

## 3. Migration 版本与文件命名

使用顺序版本时建议格式：

```text
VNNN__owner_bounded_purpose.sql
```

- 版本在自己的迁移历史内唯一且严格递增；不同数据库不比较版本号。
- `owner` 表达拥有模块或技术组件；`bounded_purpose` 使用有意义的 `snake_case`。
- 一个版本只完成一个有界目的，不混入无关模块或不同风险等级操作。
- 版本分配前搜索实际迁移目录和 Git 历史；并行开发发生碰撞时重新分配，不依赖合并顺序。
- 不以本机时间或随机值规避版本协调，除非采用项目明确选择了时间版本方案并有排序规则。

项目使用其他 Migration 工具时保留同样的“唯一顺序、单一目的、可追踪所有者”原则。

## 4. 已共享 Migration 不可变

满足任一条件即视为已共享：

- 已进入 Commit、PR、CI、发布候选或他人可获取的分支；
- 已被任一非一次性数据库记录到迁移历史；
- 已被其他开发者、环境或制品作为输入。

已共享 Migration 和伴随配置保持原始字节不变。发现错误时新增更高版本前向修复；无法证明从未共享时按已共享处理。禁止通过 repair、手工修改 History 或更改旧文件让校验和重新匹配。

## 5. 允许与禁止

正式 Schema 演进默认使用确定顺序、可校验的版本化 Migration。除非项目 ADR 明确批准，禁止：

- 生产手工执行未进入版本库的 DDL；
- out-of-order、自动 repair 或启动时静默 baseline；
- 用 `IF NOT EXISTS`、捕获异常等方式掩盖预期漂移；
- 在 Migration 中写测试租户、默认管理员、密码、Token、固定 Secret 或环境 URL；
- 用 Trigger、Function、Procedure 或动态 SQL 隐藏普通业务流程；
- 把大规模业务回填塞入应用启动事务。

Repeatable、Undo 或代码 Migration 是否允许由项目 Profile 决定；启用时必须说明所有权、重复执行语义、审计和恢复方式。

## 6. Schema 编写规则

### 6.1 表、列和所有权

- 新表同时定义主键、必要唯一约束、外键、基础索引和 Catalog 注释。
- 新列说明业务含义、单位、范围或敏感等级；注释语言由项目 Profile 统一。
- 每张表只有一个 owning module；其他模块通过拥有方公开 API 访问。
- 多租户或资源归属事实必须显式保存隔离键，或通过不可变复合外键唯一推导。
- 跨隔离边界的唯一性、外键和关键查询必须包含隔离维度，不能只依赖入口过滤。
- 主键、约束和索引显式命名，遵守数据库标识符规范。

### 6.2 约束和数据类型

- 时间点、业务日期和时区语义分开建模；精确类型由数据库 Profile 指定。
- 金额使用最小货币单位整数或显式精度十进制，禁止浮点类型。
- 外部不透明 ID 与内部技术 ID 分开保存，不根据示例格式强行解析。
- 状态和类型约束必须考虑 `NULL/UNKNOWN` 语义，可空列显式封闭空值分支。
- 关键跨表关系使用数据库约束保护，应用校验不能替代。
- RLS 只作为纵深防御，不能替代应用授权和复合约束；启用时用实际低权限运行角色验证。

### 6.3 锁与长事务

- 评估每个 DDL 的锁级别、预计时长、磁盘/日志增长和回退方式。
- 热表大型索引、约束验证和列收紧应按数据库能力分阶段执行。
- 大批回填使用有上限、可重入、可观测的维护任务，不能在普通启动 Migration 中单事务完成。
- 锁和语句超时由 Migration 或发布步骤显式设置，并在真实数据库验证失败语义。
- 非事务 DDL 必须独立成版本，不能和需要原子回滚的操作混合。

## 7. Expand → Migrate → Contract

破坏性或不兼容变化跨发布执行：

1. **Expand**：增加兼容列、表或约束，旧应用仍可运行；
2. **Migrate**：新应用兼容读写，使用有界任务回填并验证差异；
3. **Contract**：所有受支持版本不再依赖旧结构后，再收紧或删除。

禁止直接删除或重命名仍被已部署应用使用的对象。Schema 变化和业务数据回填原则上分离；只有数据规模有硬上限、短事务可完成且锁影响已验证时，才在独立版本中转换数据。

应用回滚只能回到兼容当前 Schema 的版本。默认前向修复，不自动执行 Down Migration。

## 8. 开发流程

### 8.1 变更前

1. 确认数据所有者、隔离维度和当前最高版本；
2. 搜索 SQL、持久化代码、Codegen、测试、契约和固定版本断言；
3. 判断是兼容扩展、数据迁移还是收缩，并写应用部署顺序；
4. 评估数据库角色、锁、索引、容量、备份和恢复影响。

### 8.2 同批闭合

一个数据库变更按实际影响同时包含：

- 新 Migration；
- 持久化实现和 Codegen 配置；
- 空库、升级、约束负向、隔离和并发测试；
- 受影响 API、事件、状态机、文档和运维说明；
- 固定迁移数量或最高版本断言更新。

不提交生成代码、数据库 dump、真实业务数据、容器 volume 或本地 Migration History，除非项目 Profile 明确要求且有安全审查。

## 9. Codegen 规则

项目使用数据库代码生成时：

1. 从一次性、空白且版本受控的真实数据库开始；
2. 执行该交付物的完整 Migration；
3. 按 owning module 的对象白名单生成到独立构建目录；
4. 生成类型只作为编译输入，不提交且不进入跨模块 API；
5. 编译手写源码并验证模块边界和生产类路径；
6. 停止并清理临时数据库。

禁止从个人开发库、共享库、生产备份或 SQL 文本猜测结果生成。Codegen、Meta、容器测试依赖和生成启动器不得进入生产运行类路径。

如果项目不使用 Codegen，应从检查清单移除相关项，不能保留永远跳过的僵尸任务。

## 10. 验证要求

最低验证由项目 Profile 给出实际命令，并覆盖：

- **空库**：执行全部 Migration，第二次执行无新增变化；
- **升级**：从上一个受支持版本只执行新增 Migration；
- **约束**：主键、唯一、外键、检查约束、Catalog 和索引；
- **隔离**：同边界正向和跨边界负向；
- **并发/锁**：真实数据库多连接测试，不用 JVM 锁模拟；
- **查询**：代表性数据的执行计划、索引、锁等待和响应时间；
- **权限/RLS**：迁移角色和低权限运行角色分别验证；
- **Codegen**：完整 Schema 生成，空匹配和跨所有者混入失败。

容器或数据库不可用导致的跳过不算验证通过。提交说明必须明确执行、跳过和原因。

## 11. 发布、失败与恢复

生产发布至少包含：

1. 备份并验证恢复入口；
2. 校验数据库 History 与制品 Migration checksum；
3. 由单一受控执行者运行 Migration；
4. 启动不立即领取新任务的应用副本并健康检查；
5. 开启 Worker/流量并执行数据库和核心业务 Smoke。

生产多副本不能无控制地并发执行 DDL。迁移账号与应用运行账号应分离，运行账号默认无 DDL 权限。

Migration 失败时停止发布，不自动 repair、不跳过版本、不手工标记成功。保留失败日志和数据库状态，判断事务边界；已共享版本通过新版本前向修复。

## 12. 检查清单

- [ ] 项目 Profile 已声明数据库、Migration、目录、版本、数据访问和验证命令。
- [ ] 新版本唯一、有界，未修改已共享 Migration。
- [ ] 表/列注释、主键、约束、索引和所有权完整。
- [ ] 隔离维度进入数据库约束和负向测试。
- [ ] 已评估锁、容量、超时、回填、兼容和恢复。
- [ ] Schema、应用、Codegen、测试和文档同批闭合。
- [ ] Codegen 来自完整 Migration 后的真实数据库，生成物未进入生产制品。
- [ ] 真实数据库测试实际执行，未把跳过当作通过。
- [ ] staged diff 不含 Secret、dump、本地 History 或构建产物。
